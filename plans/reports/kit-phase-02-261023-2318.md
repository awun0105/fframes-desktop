# fframes-kit, shapes, paths and geometry animations: measurements

Date: 2026-10-23. Windows Server VM, 32 threads, CPU renderer (`--renderer cpu`), release build.

## Result

`fframes-kit` now has `Geometry` and `Shape`, 26 shapes (the Manim and Remotion sets) and
`TextPath`, `paths` (Remotion's `@remotion/paths` names plus `align_points`), the Manim
animations that need geometry, the morphs, and the timing groups. The gallery has one scene
per component and Manim's `SquareToCircle`. Nothing outside `components/`, `docs/components/`
and `plans/` changed.

## Bench

Same method as before: `components_gallery_bin --renderer cpu render <Scene> -o <file>.mp4`,
150 frames at 1920x1080, five interleaved runs, wall time including process start.

| Pair | Hand-written (ms) | Kit (ms) | Median H | Median K |
| --- | --- | --- | --- | --- |
| `BenchHandWritten` / `BenchKit` (the card) | 913, 437, 449, 643, 417 | 468, 461, 551, 449, 525 | 449 | 468 |
| `BenchShapesHandWritten` / `BenchShapesKit` | 495, 582, 492, 362, 474 | 451, 459, 359, 427, 393 | 492 | 427 |

The card pair is 4% apart, the shape pair has the kit 13% faster; runs vary by about 20%,
so both are noise and inside the 10% budget. The new shape pair answers the phase's risk
note: 60 static shapes fading in, hand-written as `<circle>`, `<rect>` and a `<path>` with
path data written once, against kit `Circle`, `Square` and `Star` with `FadeIn`. The kit
rebuilds each shape's path from its props every frame and passes it as segments, not as a
string, so no `d` string is formatted or parsed; the cost does not show. Both scenes draw
the same picture (`strip BenchShapesHandWritten@1.5s,BenchShapesKit@1.5s`).

## Deviations from the phase file

- **Animation on the path, not on a wrapping `<g>`.** An animation changes a `Look`
  (transform, opacities, the drawn part of the outline) that goes into the shape's own
  `<path>` attributes: `transform` as a matrix, `stroke-dasharray`/`stroke-dashoffset` for
  `Create`. The path itself never changes except in morphs. The bench above shows the cost.
- **`d` without strings.** With the `compile-time-svgtree` feature of fframes (every
  renderer build), `d` and `transform` go into the tree as segments and a matrix. Without it
  (the kit's own tests, any `default-features = false` build), `svgr!` formats them; two
  small wrapper types (`PathData`, `Matrix`) give both.
- **Manim's `Transform` is `Morph` in the prelude**, because the prelude keeps fframes'
  `Transform` (the SVG transform); `fframes_kit::animate::Transform` has the Manim name.
- **Animation props are plain-data enums**: `enter: Option<EnterAnim>`,
  `exit: Option<ExitAnim>`, `emphasis: Option<Emphasis>`, filled with `.into()`.
- **Group timing places children with `Sequence`s** instead of setting a `delay` on them:
  child time is local, so a child's own enter animation starts with its sequence.
- **Remotion's `Arrow` is `BlockArrow`**; `Arrow` is Manim's. Remotion's `Triangle` is
  Manim's equilateral `Triangle` (pointing up). `Rect` is Remotion's (filled), `Rectangle`
  Manim's (outline).
- **`TextPath`** (glyph outlines) is the Manim `Text` for `Write`. Its outlines come from
  `MediaProvider::get_all_font_data` and `ttf_parser`, laid out like `Ui::measure` (advances,
  no kerning), and are cached once per font file, size and text in a bounded process-wide
  cache. `FontFace` gives no access to the font data, so the family and weight are matched
  on the font files' name tables.
- **`Ui::for_scene`** (new). Scenes get the video's `FFramesContext`, whose
  `duration_in_frames` is the whole video's (`render_scenes` in
  `fframes/src/fframes_context.rs`). `Ui::new` in a scene therefore gave exit animations the
  video's end: phase 1's `FadeOut` scene never faded. `Ui::for_scene(frame, ctx, theme, self)`
  takes the scene's length from `ctx.get_scene_info`. The gallery uses it, and
  `sequence_50p.png` changed because its "scene" track now measures the scene.
- **`align_points` matches loops**: for two closed subpaths it reverses the target if it runs
  the other way and turns it to start where the summed distance to the source's points is
  smallest. Without it the square and circle start at different corners and the morph
  shrinks into a diamond on the way. Morphs run on at least 16 segments per subpath.

## Upstream note (not changed)

`strip` warns "text is cut off by the canvas edge" for gallery titles wider than about 380 px
(`SquareToCircle`, `DrawBorderThenFill`). The strip renders each tile at quarter size and
then checks the full-size text box against the small canvas. `frame` and `inspect` at full
size report nothing.

## Verification

- `cargo test -p fframes-kit --all-features`: 42 unit tests and 12 doctests (every block of
  `docs/components/components.md` and the crate docs) pass.
- `cargo test --release -p components-gallery`: `measure` and `text_path` (glyph paths with
  the media font, the `<text>` fallback word by word for a family without a file) pass.
- `inspect` on the whole gallery: 603 frames, no problems. `inspect --pops` on
  `SquareToCircle`, `Write` and `Transform`: no pops.
- `strip SquareToCircle -n 8`: the square is created, morphs into the circle without
  twisting, and fades out. `strip Write -n 8`: glyphs drawn one after another.
- `just -f components/justfile e2e cpu`: 11 frames, 0.000% difference (new: `SquareToCircle@45%`,
  `Write@30%`, `Create@50%`, `Flash@40%`, `CurvedArrow@end`, `Callout@end`, and `Uncreate@90%`,
  which keeps the scene-length fix). `strip FadeOut@20%,FadeOut@50%,FadeOut@70%` and
  `strip Uncreate@50%,Uncreate@90%` show the exits running again.
- `just -f components/justfile check-wasm`, `clippy` and `cargo fmt --all --check` pass.
- `just -f components/justfile boundary`: the upstream path list is empty; the second part
  shows only the two root edits of phase 1 (`c2e99325`).
