# fframes-kit, core crate and contract: measurements

Date: 2026-10-23. Windows Server VM, 32 threads, CPU renderer (`--renderer cpu`), release build.

## Result

The `components/` workspace builds `fframes-kit`, the `components-gallery` example and its
editor bridge against the path `fframes` without any change to upstream code. The kit
version of the bench card draws exactly the same pixels as the hand-written one and costs the
same time.

## Bench: `BenchHandWritten` against `BenchKit`

Both scenes draw a lower-third card (accent bar, name, role) with three fades staggered by
0.1 s, 0.6 s each, ease-in-out. The hand-written scene builds two `timeline!`s per part and
frame; the kit scene uses `Sequence` and `FadeIn`. Each is 150 frames at 1920x1080. The command
was `components_gallery_bin --renderer cpu render <Scene> -o <file>.mp4`, runs interleaved
(H, K, H, K, ...), wall time including process start.

| Round | BenchHandWritten (ms) | BenchKit (ms) | Median H | Median K |
| --- | --- | --- | --- | --- |
| 1 (3 runs each) | 410, 455, 409 | 531, 373, 401 | 410 | 401 |
| 2 (5 runs each) | 543, 351, 485, 425, 428 | 373, 534, 496, 404, 426 | 428 | 426 |

`BenchKit` is within 1 to 2% of `BenchHandWritten`, inside the 10% budget. The runs vary
by about 20% between each other, so a difference below that is noise. The two output files
have the same size, and `frame BenchHandWritten@0.4s` and `frame BenchKit@0.4s` give
byte-identical PNGs.

## Text measurement

The phase's risk note expected `Ui::measure` to differ from `Frame::text_width` by a few
pixels. It does not. The core's `text_width` also sums per-character advances with no kerning
(`calc_text_width` in `fframes/src/text.rs`), so `Ui::measure` reproduces it exactly.
`gallery/tests/measure.rs` asserts equality on three strings with the gallery's DM Sans.

## Deviations from the phase file

- The gallery binary is named `components_gallery_bin`, not `components-gallery`. On Windows
  a binary with the lib's name writes the same `.pdb` file as the lib (cargo warns about the
  collision); the examples use the `_bin` suffix for the same reason. `scripts/e2e.mjs` uses
  the new name.
- `Component` is object-safe through a second trait, `DynComponent` (blanket-implemented for
  every component), with `BoxedComponent<'a> = Box<dyn DynComponent<'a> + 'a>`. A
  `self: Box<Self>` method on `Component` itself cannot have a default body, so each
  component would have had to write it.
- `Vec<T>` and `Option<T>` of components are components too, so `ui.show(list)` renders a
  `Vec<BoxedComponent>`.
- `Enter::apply` takes the `Ui` and the content only; the geometry-aware enter animations of
  the shapes phase need their own trait or an extra argument there.
- `Exit` without a known end (`ui.duration` is `None`) returns the content unchanged.
- `Theme` text styles use `&'static str` font families.

## Verification

- `cargo test -p fframes-kit --all-features`: 15 unit tests and 9 doctests (including every
  block of `docs/components/components.md`) pass.
- `cargo test --release -p components-gallery --test measure` passes.
- `cargo clippy --all-targets -- -D warnings` and `cargo fmt --all --check` pass in
  `components/`.
- `just -f components/justfile check-wasm` passes.
- `svg Theme@50%` shows the `Fill` background resolved to a 1920x1080 path (the `100%` rect
  sizes resolve against the viewBox).
- `just -f components/justfile e2e cpu` passes: 4 snapshots, 0.000% differ.
- `timeline` lists every scene by component name; `inspect` checked 120 frames with no
  problems (a zero-width progress bar warning was fixed by giving the bar a minimum width).
- At the root, `cargo metadata --no-deps` lists no package under `components/`,
  `cargo check -p fframes` passes, and the root `Cargo.lock` is unchanged.

## Unresolved questions

- `frame --scale 0.5` warns that text inside the canvas is cut off by the canvas edge; the
  numbers suggest the inspector compares full-size boxes with the scaled canvas. It is an
  upstream inspector behaviour, not a kit problem; `inspect` at full size reports nothing.
