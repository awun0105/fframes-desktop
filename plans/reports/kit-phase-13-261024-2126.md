# Kit: Remotion transitions II

Date: 2026-10-24. Machine: the Windows Server VM, CPU only, `--renderer cpu`.

## Result

Ten new presentations, `Ui::transition_progress` (Remotion's `useTransitionProgress`), and
`audio_fades` for the sound of a series are in `components/fframes-kit/src/transitions/`.
Each presentation has a gallery scene. `cargo test -p fframes-kit --all-features` passes (325
unit tests, 92 doctests). `just e2e cpu` matches every existing snapshot and adds
`dissolve_50p`, `dreamyzoom_50p`, `filmburn_50p` and `swapcards_50p`. `just e2e skia-cpu`
passes too (Dissolve 0.31%, every other frame at most 0.001%). `clippy`, `check-wasm`,
the gallery tests and `boundary` are clean. `inspect` on the whole gallery at full size
checks 3491 frames and finds nothing.

`inspect NoTransition --pops` was expected to show the one cut; it reports no problems. The
cut swaps one full-canvas panel for another, which the pop check does not count as an
element appearing, vanishing or jumping in front of another.

At `--scale 0.5` (`strip`, `inspect`) the inspector reports the panels' big labels as cut
off by the canvas edge, in older scenes such as `Fade` too: the text boxes are in
full-size units against the half-size canvas. At full size there is no such finding.

## Discrepancies between the phase file and Remotion

- **`LinearBlur`.** The phase asked for "a directional blur with an angle". Remotion's
  `linearBlur()` has only `intensity`, and the GL shader averages a 6 by 6 grid, which is a
  2D blur. A first version with an `angle` (turn, blur along x, turn back) drew a horizontal
  smear at 30° on the CPU backend: resvg blurs along the canvas axes whatever the transform.
  The kit now follows Remotion (both axes) and has `axes: (f32, f32)` to weigh x and y, so
  a horizontal-only or vertical-only blur still works on both backends.
- **`Dissolve`.** The phase asked for a seeded `feTurbulence` threshold mask; Remotion orders
  the burn by the luminance of each pixel. The entering side is drawn on top and the
  `Presentation` sees only its own content, so it cannot read the exiting pixels; the kit
  keeps the noise threshold and maps Remotion's props onto the edge: `line_width` is the
  glow width in noise units, `spread_color` and `hot_color` its outer and inner colours,
  `pow` narrows the hot core to `line_width / pow`, and `intensity` is the glow's opacity.

## Audio fades

`audio_fades(&[SeriesLength], fps)` places the items with the series' own `layout`, so a
shortened or skipped transition fades as it is drawn. Each sequence gets `start`, `end`,
`fade_in` and `fade_out` in seconds from the series start; `AudioFade::apply` sets the fades
on an `AudioTrack`. `TransitionSeries::audio_fades(fps)` does the same from a built series.

## Blur cost (CPU backend, 1080p, 28 threads)

`render <scene>` of a 2.2 s gallery scene (66 frames, 24 of them in the transition),
wall-clock including start-up and encoding:

| Scene | Seconds |
| --- | --- |
| `Fade` (no filter) | 1.20 |
| `BlurSlide` | 1.26 |
| `DreamyZoom` | 1.70 |
| `CrossZoom` | 2.12 |
| `LinearBlur` | 2.43 |
| `Dissolve` | 2.44 |
| `FilmBurn` | 2.64 |

The filtered transitions cost up to about 60 ms more per transition frame than a fade. The
filter region is the item's own box (`0 0 100% 100%`), not the blur effect's `-50% 200%`
region, which would blur four times the area.

## CPU and Skia parity

The first version passed `e2e cpu` but not `e2e skia-cpu`: Dissolve differed by 2.7%,
DreamyZoom by 0.58%, and outside the e2e set BlurSlide by 11% and CrossZoom by 1.2%.

- **Blur at the canvas edge.** A zoomed or moved side reaches past the canvas. The Skia
  backend blurs those pixels in; the CPU backend never renders them, so its blur faded to
  transparent at the canvas edges and they darkened. `blurred` now clips the side to
  `size` before blurring, so both blur the same pixels, then multiplies the alpha by 4 so
  opaque content stays opaque to the edge. Four, not two: the CPU backend's box blur at
  large deviations leaves about a quarter of the alpha at a straight edge (with 2, BlurSlide
  still differed by 6%; with 4, by 0.0002%). The cost: a translucent side turns opaque where
  the blur leaves it a quarter opaque. The docs say the presentations expect sides that
  cover the canvas. `edgeMode="duplicate"` was dropped; resvg ignores it.
- **Dissolve thresholds.** The CPU backend rounds the noise to 8 bits before the colour
  matrix, so a steep threshold turns each rounding step into a visible alpha step. The
  reveal ramp went from 0.01 to 0.05 noise units, and the glow ramps reach 0.05 past it so
  the burn edge stays visible (0.08 also matched, at 0.05%, but the glow turned muddy).

## Filter ids

Every id comes from the series' transition id (the component `key`). Both sides of a
transition can blur in the same frame, so `blurred` adds `-blur-in` or `-blur-out` to the
filter and `-area` to its clip path; `FilmBurn` adds `-gradient` and `-noise`.
