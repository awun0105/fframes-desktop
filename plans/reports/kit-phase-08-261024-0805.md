## What was built

- **Engine (`desktop/crates/studio-engine`):**
  - `props.rs` holds the session: the document, its generation, the known hash, a notice, and history.
  - `controller/props.rs` adds `Set`, `BeginGesture`/`EndGesture`, `Undo`/`Redo`, `props_snapshot`, `props_for_export` and `observe_props_file`.
  - Its gates are the timing gates minus the scene report. An invalid `props.json` disables editing and export.
- **Shared with timing:**
  - `timing/file.rs` became `DocFile` with `read_doc`/`write_doc`/`recover_doc`. Timing keeps its wrappers and messages.
  - `History<D>` is generic over the document.
  - `Boundary::PropsWrite` injects faults.
  - `revision::run_time_document` leaves both files out of the build revision and the build copy. `props.json` stays `FileKind::Other`, so there is no inventory version bump.
- **Preview:**
  - `PreviewCoordinator::set_props` applies once per generation: before the first frame of a staged worker, and on the displayed worker, followed by a re-render of the same seek.
  - `want_props_info` asks `PropsInfo` for the selection after the wanted frame is drawn, and again after each seek or props change.
  - The worker client has `set_props`, `props_info` and `supports_props`, with size and generation checks.
- **Export:**
  - `ExportRequest.props_json` is passed as `--props-file`.
  - `ExportCapabilities.props` (`#[serde(default)]`) must be true. An older worker reads as false, and the export is refused with its reason.
  - The runtime has `print_export_capabilities_with_props`.
- **UI:**
  - `props_panel.rs` is the panel, under the sidebar's new **Props** tab. Controls by kind:
    - text, number and integer: a text field;
    - a number with a range: also a slider; a drag is one gesture;
    - colour: a hex field and a swatch;
    - toggle: a toggle;
    - choice: buttons.
  - Each field has a reset to the code's value, and the panel has undo and redo.
  - `shell/props_edits.rs` queues edits while a command runs; a value replaces a queued value of the same field.
  - The selection syncs where the agent task scope is installed and on Cycle. Props telemetry is in the observation JSON.

## Departures, with reasons

- **The kit manifest fix (`a848a480`).** Under the desktop toolchain (cargo 1.98.1), the `kit-props` fixture could not load the kit: "`default-features = false` cannot override workspace's `default-features`". cargo 1.99 only warns.
  - The workspace now declares `default-features = false`, and the gallery adds `cpu_renderer`, so its features are unchanged.
  - After the fix: e2e 64/64 at 0.000 %, clippy on all targets and features, the tests, and the wasm bridge.
- **The props module is a file, not a folder.** It is `studio-engine/src/props.rs` rather than `props/`: the file write and history are shared with timing, so one file is enough.
- **The end-to-end check is an ignored app test** (`app/tests/kit_props_roundtrip.rs`), like `worker_roundtrip.rs`. It uses the compiled fixture and checks:
  - the export capabilities report `props`;
  - the frame names `Circle "dot"`;
  - `PropsInfo` gives the schema and the code values;
  - `SetProps` redraws (outline about 3x longer at 3x the radius);
  - `None` restores the code's values.

## Verification

- **Engine:**
  - `cargo test -p studio-engine --test props`: 6 tests (writes, undo/redo/reset, a 40-step gesture as one write and one undo with the build kept, crash recovery on open, outside change, invalid file, agent task).
  - Worker client: 2 unit tests.
  - A real-process coordinator test against the fake worker: `apply_props` changes the frame, `PropsInfo` values, and `None` restores them.
- **Export through the fixture (manual):** `kit-props.exe --export-v1 --output x.mp4 --props-file props.json`, with the radius set to 120.
  - Frame 0, decoded to gray with ffmpeg: 546 lit pixels without the document, 1719 with it (about 3.1x, as in the preview).
  - A missing `--props-file` fails the export with "props file … does not exist".
- **Full suites:** `cargo test -p studio-engine -p studio-ui -p studio-project` all pass. That includes 3 panel parsing tests and the queue replacement test.
- **Round trip:** `cargo test -p fframes-studio --test kit_props_roundtrip -- --ignored` passes.
- **Clippy:** `cargo clippy --workspace --tests -- -D warnings` in `desktop/` is clean.
- **Protocol and runtime:** clippy `-D warnings` on the libraries is clean, and the tests pass.
- **Components:** clippy (all targets, with default and with all features), tests, the wasm bridge, and `node scripts/e2e.mjs cpu` (64 frames at 0.000 %).
- **Boundary:** the three queries were run directly, because `just` finds no bash on this VM. The first and third print nothing. The second prints only phase 1's `exclude` word and pointer line.

## Unresolved

- **The manual run in the Studio app was not done** (select, edit, undo, outside edit). The headless tests cover the engine and the worker; the panel's rendering was not seen.
- **Timeline thumbnails are not refreshed after a props change.** They keep the code's values until they are asked for again.
- **Upstream deprecation.** `cargo clippy --tests` on `fframes-studio-runtime` fails on `DynamicMediaProvider::new` (`preview_worker.rs:1198`, upstream commit `df75bdf4`). It is not from this phase; it was left as it is.
- **`Option<Color>` uses `null` for none.** The panel has no "none" control yet; resetting the field returns the code's value.
- **`props.json` keeps `FileKind::Other`.** An agent's candidate that changes only `props.json` is not classified like a timing-only change.
- **`just boundary` needs bash**, which this VM does not have.
